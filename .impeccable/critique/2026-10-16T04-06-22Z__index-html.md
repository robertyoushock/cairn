### Priority Issues

- **[P1] Mobile Sheet Toggle Does Not Hide the Panel**
  - **Why it matters:** On mobile (<760px), tapping the floating "Map" button toggles `#panel-toggle` and adds `.panel-closed` to `.app`, but `style.css` contains no CSS rule hiding `.panel`. The sheet stays fixed at 58dvh, obscuring more than half the map.
  - **Fix:** Add `.panel-closed .panel { display: none; }` (or `transform: translateY(100%);`) in `style.css` under `@media (max-width: 760px)`.
  - **Suggested command:** `/impeccable adapt`

- **[P1] Dual Competing Search Bars in Step 1**
  - **Why it matters:** `#place-text` ("Search for a place or address") and `#find-text` ("Find map data") sit stacked in Step 1 with identical visual weight. Users frequently type locations into the data finder and boundary types into the geocoder.
  - **Fix:** Subordinate the address geocoder as a floating map control ("Jump to city/address") or unify them into a single search input.
  - **Suggested command:** `/impeccable distill`

- **[P2] Fragmented Styling Controls Between Step 2 and Step 3**
  - **Why it matters:** Fill color, outline color, and outline width live under Step 2 (`#list-colors`), while opacity, labels, and shape detail live inside Step 3 (`details#look`). Users tweaking appearance must jump between two steps.
  - **Fix:** Consolidate all cartographic styling controls into a single "Map Appearance & Export Styling" container.
  - **Suggested command:** `/impeccable layout`

- **[P2] Missing Skip Links for Keyboard Users**
  - **Why it matters:** Keyboard-only and screen reader users must tab through dozens of search fields, suggestion chips, and boundary cards before reaching the map controls or curated list.
  - **Fix:** Add accessible `<a href="#map" class="sr-only-focusable">Skip to map</a>` and `<a href="#list" class="sr-only-focusable">Skip to list</a>` skip links.
  - **Suggested command:** `/impeccable polish`
